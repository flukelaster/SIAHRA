# ระดับการเผชิญน้ำ (Flood exposure) — วิธีคำนวณ

**ชนิดของชั้นข้อมูล: ภาพประกอบ (illustrative)**
ชั้นนี้ **ไม่ใช่การพยากรณ์** ไม่ใช่ค่าความน่าจะเป็น และไม่ใช่คะแนนความเสี่ยง
มันคือการ **จัดอันดับค่าที่สถานีรายงานมาแล้ว** ตามตารางเกณฑ์ที่ประกาศไว้ในหน้านี้เท่านั้น —
ไม่มีตัวเลขใดในชั้นนี้บอกว่าน้ำจะท่วมที่ไหน เมื่อไร หรือด้วยโอกาสเท่าใด
ระดับ `severe` แปลว่า "ค่าที่สถานีนี้ส่งมาอยู่ในแถบบนสุดของตาราง" ไม่ได้แปลว่า
"ที่นี่กำลังจะท่วม" และการตัดสินใจเรื่องความปลอดภัยให้ยึดประกาศของหน่วยงานราชการเสมอ

ทุกค่าใน run หนึ่ง ๆ เป็นได้แค่สองอย่าง: **ค่าที่คัดลอกมาตรง ๆ จาก ThaiWater**
หรือ **แถบ (band) ที่ค่านั้นตกอยู่** ตามตารางข้างล่าง ไม่มีการถ่วงน้ำหนัก ไม่มีการรวมคะแนน
และไม่มีการเติมค่าที่ต้นทางไม่ได้ส่งมา

## ข้อมูลนำเข้า

- **ค่าตรวจวัดจากสถานีโทรมาตร (ThaiWater สสน.)** — ปริมาณฝน 1 ชม. / 24 ชม.,
  ระดับน้ำเทียบตลิ่ง (freeboard) และ `situation_level` ที่ต้นทางประกาศเอง
- **กราฟระดับน้ำย้อนหลัง (ThaiWater `waterlevel_graph`)** — ใช้หาอัตราการเปลี่ยนแปลง
  ของ freeboard ในหน้าต่างเวลาย้อนหลัง `historyWindowH` ชั่วโมง (ค่าตั้งต้น 3 ชั่วโมง)

หน่วยและเวลาทั้งหมดเป็นของต้นทาง: มิลลิเมตร, เมตร, และเวลาไทยที่ถูกปักโซน +07:00
ตั้งแต่ชั้น ingestion แล้ว

## ตารางเกณฑ์ (threshold table)

ระดับของสถานี = **แถบที่สูงที่สุดที่ปัจจัยใด "ปัจจัยหนึ่ง" ไปถึง** (`low < elevated < high < severe`)
ไม่ใช่คะแนนรวม — สถานีหนึ่งจึงเป็น `high` เพราะฝนอย่างเดียวได้ ทั้งที่ระดับน้ำยังห่างตลิ่งหลายเมตร
ปัจจัยที่ต้นทางไม่ได้ส่งมาจะเป็น `null` และ **ไม่ถูกนับ** (ไม่ใช่ถูกนับเป็นศูนย์)

| ปัจจัย (`factors.*`) | low | elevated | high | severe |
| --- | --- | --- | --- | --- |
| `rain24hMm` — ฝนสะสม 24 ชม. (มม.) | ≤ 10.0 | > 10.0 | > 35.0 | > 90.0 |
| `rain1hMm` — ฝน 1 ชม. (มม.) | ≤ 10.0 | > 10.0 | > 30.0 | > 60.0 |
| `freeboardM` — ระยะจากผิวน้ำถึงตลิ่งต่ำสุด (ม.) | ≥ 3.00 | < 3.00 | < 1.00 | < 0.30 |
| `freeboardTrendMPerH` — อัตราที่ freeboard ลดลง (ม./ชม.) | ≥ −0.15 | < −0.15 | < −0.35 | < −0.75 |
| `situationLevel` — ระดับสถานการณ์ของ ThaiWater | 1, 2, 3 | — | 4 | 5 |

ที่มาของตัวเลขแต่ละแถว:

- **`rain24hMm`** ใช้เกณฑ์ฝนของกรมอุตุนิยมวิทยาตรง ๆ (ฝนเล็กน้อย ≤ 10.0 มม.,
  ฝนปานกลาง 10.1–35.0, ฝนหนัก 35.1–90.0, ฝนหนักมาก > 90.0 มม./24 ชม. — ในโค้ดเขียน
  เป็นขอบแบบ "มากกว่า" ที่ 10.0 / 35.0 / 90.0 ซึ่งเป็นช่วงเดียวกัน)
  แถบทั้งสี่จึงเป็นชื่อเรียกของ TMD ที่แปลงเป็นคำเดียวกันทั้งชั้นข้อมูลเท่านั้น
- **`rain1hMm`** ไม่มีเกณฑ์ทางการรายชั่วโมงของ TMD ให้อ้าง ตัวเลขสามค่านี้จึงเป็น
  **ข้อตกลงของโปรเจกต์นี้เอง** สำหรับ "จัดเรียง" ค่าที่วัดได้ ประกาศไว้ตรงนี้เป็นตัวเลข
  ไม่ใช่คำคลุมเครือ และเปลี่ยนได้ที่ `DEFAULT_EXPOSURE_THRESHOLDS` ที่เดียว
- **`freeboardM`** เป็นระยะที่วัดได้จริง (ตลิ่งต่ำสุด − ระดับน้ำ) ขอบ 0.30 ม. คือ
  "เกือบเสมอตลิ่งจนความคลาดเคลื่อนของหมุดระดับมีความหมาย" ไม่ใช่ระดับเตือนภัยของหน่วยงานใด
- **`freeboardTrendMPerH`** ตั้งไว้ค่อนข้างสูงโดยตั้งใจ เพราะแม่น้ำใหญ่ที่ยังห่างตลิ่งมาก
  ก็ขึ้นลงเร็วได้ตามปกติ ค่านี้เป็น **อัตราที่เกิดขึ้นไปแล้ว** ในหน้าต่างย้อนหลัง
  ไม่ได้ถูกต่อเส้นไปข้างหน้า
- **`situationLevel`** ส่งผ่านจาก ThaiWater ตรง ๆ ไม่คำนวณใหม่ (1 = น้ำน้อย … 5 = ล้นตลิ่ง)
  ระดับ 1–3 คือช่วงที่ต้นทางถือว่าไม่ใช่น้ำมาก จึงแมปเป็น `low` ทั้งสามค่า

## ขั้นตอนการคำนวณ

คำนวณที่ฝั่ง API (`apps/api/src/exposure/compute.ts`) เป็นฟังก์ชันบริสุทธิ์
`computeExposure(observations, hourlyLevels, thresholds, now)`:

1. **รวมระเบียนตามรหัสสถานี** — สถานีโทรมาตรของ ThaiWater หนึ่งตัวรายงานได้ทั้งฝนและระดับน้ำ
   ใช้ `station.id` เป็นกุญแจ ถ้าสถานีเดียวกันมีทั้งสองระเบียน ข้อมูลประจำตัว
   (`lat`, `lon`, `provinceCode`) ยึด **ระเบียนระดับน้ำ** เป็นหลัก เพราะเป็นระเบียนที่มีค่าตลิ่ง
   ประกอบอยู่ด้วย — ไม่มีการเฉลี่ยพิกัดหรือเดาจังหวัดในทุกกรณี
2. **หาอัตราการเปลี่ยนของ freeboard** — จากกราฟย้อนหลังเฉพาะจุดที่อยู่ในหน้าต่าง
   `historyWindowH` ชั่วโมงก่อน `now` ใช้จุดแรกกับจุดสุดท้ายของหน้าต่าง
   `trend = −(ระดับน้ำล่าสุด − ระดับน้ำจุดแรก) / จำนวนชั่วโมงระหว่างสองจุด`
   (เครื่องหมายลบเพราะน้ำขึ้น = freeboard ลด) ค่านี้เป็น `null` เมื่อ **จุดที่ใช้ได้ในหน้าต่าง
   มีน้อยกว่าสองจุด** หรือ **จุดที่ใช้ได้ทั้งหมดตกอยู่ที่เวลาเดียวกัน** (ช่วงเวลาเป็นศูนย์)
   จุดที่ใช้ได้ = มีเวลาที่อ่านได้ มีค่าระดับน้ำที่เป็นตัวเลข และอยู่ในหน้าต่าง
   ถ้าต้นทางส่งประวัติของสถานีเดียวกันมาหลายก้อน จุดทุกก้อนถูกนำมารวมกัน ไม่มีก้อนใดถูกทับหาย

   **กฎตัดสินเมื่อสองจุดมีเวลาเท่ากัน** — จุดถูกเรียงตามเวลา แล้วเวลาที่เท่ากันเรียงตามค่า
   ระดับน้ำจากน้อยไปมาก ผลคือที่เวลาแรกใช้ค่าน้อยที่สุด และที่เวลาสุดท้ายใช้ค่ามากที่สุด
   นี่เป็น **ข้อตกลงที่เลือกไว้** ไม่ใช่ผลพลอยได้: มันตัดสินค่าที่ขัดกันเองที่เวลาเดียวกัน
   ไปทาง trend ที่ติดลบที่สุด (แถบที่หนักกว่า) และที่สำคัญกว่านั้นคือทำให้ผลลัพธ์
   **ไม่ขึ้นกับลำดับที่ต้นทางส่งจุดมา** ถ้าไม่มีกฎนี้ ระดับที่เผยแพร่ของสถานีจะพลิกได้
   เพียงเพราะอาเรย์สลับที่

   **ขอบเขตของการเอียงนี้** — มันทำงานเฉพาะตอนที่เวลาหนึ่งมีค่าที่ขัดกันเองสองค่าเท่านั้น
   แตะเฉพาะ `freeboardTrendMPerH` ไม่แตะปัจจัยอื่น **ยกแถบขึ้นได้อย่างเดียว ลดไม่ได้**
   (เพราะระดับสถานีคือแถบที่สูงที่สุดในบรรดาปัจจัยทั้งหมด) และสร้าง trend ขึ้นมาเองไม่ได้
   — ยังต้องมีจุดที่ใช้ได้อย่างน้อยสองจุดที่เวลาต่างกันอยู่ดี

   ทางเลือกที่ดูเป็นกลางกว่าถูกพิจารณาแล้วและแย่กว่า: การเฉลี่ยสร้างค่าที่ไม่มีสถานีไหน
   เคยรายงานขึ้นมาใหม่ แล้วป้อนเข้าสูตรที่เอกสารนี้เผยแพร่ตรง ๆ ส่วนการปฏิเสธไม่คำนวณ
   trend เมื่อเจอเวลาที่ขัดกันเอง จะทำให้จุดซ้ำเพียงจุดเดียวตอนต้นหน้าต่าง **ลบแนวโน้ม
   น้ำขึ้นจริงที่กินเวลาหลายชั่วโมงทิ้งทั้งอัน** และถ้าไม่มีปัจจัยอื่นให้จัดแถบ สถานีนั้น
   จะได้ `low` ซึ่งเป็นคำเดียวกับ "วัดได้และอยู่แถบต่ำสุด" — กฎที่หน้าตาเป็นกลางแต่ฟอก
   แนวโน้มที่รู้อยู่แล้วให้กลายเป็นคำที่อ่านแล้วดูปลอดภัย แย่กว่าการเอียงที่ประกาศไว้

   **หมายเหตุความไม่สมมาตร** — กฎ "เอียงไปทางหนัก" ใช้กับจุดประวัติเท่านั้น ส่วนกรณีที่
   ต้นทางส่ง *เรกคอร์ดสถานี* ซ้ำกันที่เวลาเดียวกันเป๊ะ ตัวตัดสินคือการเทียบสตริงของเนื้อหา
   ซึ่ง **จงใจไม่อิงความรุนแรง** — สองเรกคอร์ดนั้นมีเวลาเท่ากันทุกประการ จึงไม่มีข้ออ้าง
   ทางข้อมูลใดให้เลือกฝั่งที่หนักกว่า มีแต่ต้องเลือกให้เหมือนเดิมทุกครั้ง
3. **จัดแถบทีละปัจจัย** ตามตารางข้างบน แล้วเอา **แถบที่สูงที่สุด** เป็นระดับของสถานี
   สถานีที่ไม่มีปัจจัยใดเลยที่ใช้ได้ ได้ `low` พร้อม `factors` ที่เป็น `null` ทั้งหมด —
   ซึ่งอ่านว่า "ไม่มีข้อมูลที่จะจัดอันดับ" ไม่ใช่ "ปลอดภัย"

   **คำว่า `low` จึงกินความสองอย่าง และแผนที่ต้องแยกมันออกจากกัน** ตั้งแต่ E10.4
   ฝั่งเว็บอ่านความต่างนี้จาก `factors` ที่ run ส่งมาโดยตรง (`hasUsableFactor()` ใน
   `apps/web/src/lib/exposureStyle.ts` ใช้กฎเดียวกับ `bandOfRising`/`bandOfFalling`
   ทุกตัวอักษร: `null` หรือค่าที่ไม่ใช่จำนวนจำกัด = ไม่เกิดแถบ, `situationLevel`
   ที่ไม่ใช่ `null` นับว่าใช้ได้, `rain24hMm: 0` คือค่าที่ **วัดมาแล้ว** จึงเป็น "ต่ำสุด
   ที่วัดได้") — **สัญญาใน `packages/shared-types` ไม่ถูกแก้** เพราะสิ่งนี้เป็นเรื่องของ
   การแสดงผล ไม่ใช่ค่าใหม่ที่ใครวัดมา บนแผนที่ "ต่ำสุดที่วัดได้" เป็นจุดทึบสีม่วงขนาดเล็ก
   ส่วน "ไม่มีปัจจัยใดวัดได้" เป็น **วงแหวนกลวงเส้นประสีเทาพร้อมเครื่องหมาย `?`**
   ขนาดเท่าแถบ `high` (มีป้ายข้อความกำกับด้วย แต่จำกัดจำนวนไม่ให้บังกันเอง — ตัวที่
   แบกความหมายคือวงแหวนซึ่งวาดครบทุกสถานี) — ต่างกันที่ **รูปทรง** จึงแยกออกได้แม้ในภาพขาวดำ และ
   legend เรียกชื่อทั้งสองสถานะพร้อมจำนวนสถานีจริงของแต่ละสถานะ

   ส่วนที่ระบายลงบนภูมิประเทศถูกคุมด้วยชั้นพื้นที่ลุ่มต่ำ (เฉพาะที่ลุ่มต่ำเท่านั้นที่ติดสี
   และเฉพาะแถบที่สูงกว่าต่ำสุด) แต่ **หมุดรายสถานีจงใจไม่ถูกคุมด้วยที่ลุ่มต่ำ** ไม่งั้น
   สถานีที่ไม่มีใครวัดซึ่งตั้งอยู่บนที่ดอนจะไม่ปรากฏอะไรเลยบนแผนที่
4. **เรียงสถานีตาม `stationId`** แล้วจึงคำนวณ `runId` — ลำดับที่ต้นทางส่งมาไม่คงที่
   ถ้าไม่เรียงก่อน run ที่เนื้อหาเหมือนกันจะได้ id ต่างกัน

การคำนวณเป็น **deterministic**: อินพุตชุดเดียวกันให้ผลลัพธ์ไบต์ต่อไบต์เหมือนเดิมเสมอ
ไม่มีการอ่านนาฬิกาภายในฟังก์ชัน (เวลาปัจจุบันถูกส่งเข้ามาเป็นพารามิเตอร์ `now`)
และไม่มีการสุ่ม

"อินพุตชุดเดียวกัน" หมายถึง **เนื้อหาเดียวกัน ไม่ว่ามาในลำดับใด** ทุกจุดที่ต้นทางอาจส่ง
ของซ้ำหรือสลับลำดับมาจึงตัดสินด้วย total order ที่ประกาศไว้:

- **ระเบียนสถานีซ้ำ** (ฝนหรือระดับน้ำที่ `station.id` เดียวกัน) — เลือกด้วยกุญแจ
  `(เวลาวัด มาก→น้อย, สตริงของระเบียน น้อย→มาก)` ระเบียนที่มีเวลาวัดจริง **ชนะเสมอ**
  ระเบียนที่ไม่มีเวลาหรือเวลาอ่านไม่ออก จึงไม่มีทางที่สถานีจะรายงาน `observedAt: null`
  ทั้งที่มีค่าที่วัดพร้อมเวลาอยู่ในชุดข้อมูล
- **จุดประวัติที่เวลาเท่ากัน** — ตัดสินตามกฎในข้อ 2 ข้างบน
- **ประวัติของสถานีเดียวกันหลายก้อน** — รวมจุดทุกก้อน ไม่ทับกัน
- **ลำดับของสถานีในผลลัพธ์** — เรียงตาม `stationId` ก่อนคิด `runId` เสมอ (ข้อ 4)

## รูปแบบของ run id

- รูปแบบ: `YYYYMMDDTHHMMSSZ-<hash 16 ตัวอักษรฐานสิบหก>`
- ตัวอย่าง: `20260819T093000Z-3f7a1c02b95e4d18`
- ส่วนหน้า = `computedAt` ในรูปแบบ UTC แบบย่อ (ตัด `-`, `:` และเศษมิลลิวินาทีออก)
  ทำให้ชื่อไฟล์เรียงตามเวลาได้เอง
- ส่วนหลัง = FNV-1a 64 บิต ของเนื้อหา run (`inputs`, `layer` และ `stations` ที่เรียงแล้ว
  โดยไม่รวมตัว `runId` เอง) เขียนเป็นเลขฐานสิบหก 16 ตัว เติมศูนย์ด้านหน้า
  ใช้เพื่อ **ตรวจว่าเนื้อหาเปลี่ยนหรือไม่** ไม่ใช่เพื่อความปลอดภัยเชิงรหัสลับ

run ที่ถูกเผยแพร่แล้วเป็น **immutable** — คีย์ `exposure/runs/{runId}.json.gz` ไม่ถูกเขียนทับ
และไม่ถูกแก้ย้อนหลัง ค่าที่เปลี่ยนไปคือ run ใหม่เสมอ

## จังหวัดของสถานี (`provinceCode`)

`StationExposure.provinceCode` คือ **สำเนา ณ เวลาที่คำนวณ** ของ `StationRef.provinceCode`
ที่ ThaiWater ส่งมา คัดลอกมาตรง ๆ และ **คง `null` ไว้ถ้าต้นทางไม่มีค่า**

- ถ้าเป็น `null` แปลว่าระเบียนต้นทางไม่มีรหัสจังหวัด — สถานีนั้นจะไม่ปรากฏใน endpoint
  รายจังหวัด และปรากฏเฉพาะใน run ระดับประเทศ นี่คือการบอกตามจริง ไม่ใช่ช่องว่างที่ต้องเดาเติม
- **ห้ามเดาจากพิกัด** ขอบเขตการปกครองไม่ได้ตัดสินด้วยเรขาคณิตของเรา
- **ห้ามหาใหม่ตอนเรียก API** จากตารางสถานีปัจจุบัน มิฉะนั้น run เก่าจะถูกแบ่งจังหวัด
  ด้วยรายชื่อสถานีของวันนี้ สถานีที่ถูกปลดระวางจะหายจาก run ที่มันเคยอยู่ และ run id เดิม
  จะตอบไม่เหมือนกันในแต่ละวัน
- **ห้ามเติมย้อนหลังลง run ที่เผยแพร่ไปแล้ว** สถานีที่เพิ่งได้รหัสจังหวัดจะได้ใน run ถัดไป

## สิ่งที่ **ไม่ได้** รวมอยู่ในชั้นนี้

- **เรดาร์ฝน (TMD)** — ยังไม่ถูกใช้เป็นปัจจัยเลยในเวอร์ชันนี้ (จะพิจารณาใน E10.5
  ถ้าเพิ่มเข้ามาจะมีตารางแปลงค่าพิกเซลประกาศไว้ในหน้านี้)
- **ความลึกของน้ำจากแบบจำลองความสูง (DEM depth)** — ไม่มีการคำนวณว่าน้ำจะลึกเท่าใด
  ที่จุดใด ชั้น "พื้นที่ลุ่มต่ำ" เป็นคนละชั้นและเป็นเรื่องรูปทรงภูมิประเทศล้วน ๆ
  (ดู [lowland](/methodology/lowland))
- **แบบจำลองชลศาสตร์ (hydraulics)** — ไม่มีการไหล ไม่มีการทดน้ำ ไม่มีการแผ่ของน้ำ
  ไม่มีสมการใด ๆ ของการเคลื่อนที่ของน้ำ
- **สิ่งที่มนุษย์สร้าง** — คันกั้นน้ำ ประตูระบายน้ำ สถานีสูบน้ำ และการบริหารจัดการน้ำ
  ไม่ได้อยู่ในการคำนวณนี้เลย
- **การกระจายค่าเชิงพื้นที่** — ค่าอยู่ที่ "จุดสถานี" เท่านั้น ไม่มีการ interpolate
  ระหว่างสถานี พื้นที่ที่ไม่มีสถานีคือพื้นที่ที่เราไม่มีข้อมูล ไม่ใช่พื้นที่ที่ค่าต่ำ

## ข้อจำกัดอื่นที่ต้องรู้

- **ความหนาแน่นของสถานีไม่เท่ากัน** — บางลุ่มน้ำมีสถานีถี่ บางจังหวัดแทบไม่มีเลย
  จำนวนจุดบนแผนที่จึงสะท้อนเครือข่ายการวัด ไม่ใช่สภาพน้ำ
- **ค่าที่ค้างยังถูกจัดแถบตามปกติ** — ฟังก์ชันนี้ไม่ตัดค่าที่เก่าทิ้ง สถานีที่หยุดส่งข้อมูล
  จะคงระดับล่าสุดไว้พร้อม `observedAt` เดิมของมัน ไม่ใช่หายไปเงียบ ๆ ผู้แสดงผล
  (แผนที่/legend) มีหน้าที่แสดงอายุของค่าและหรี่จุดที่ค้างเสมอ
- **`observedAt` ของสถานีคือเวลาที่ "เก่าที่สุด" ในบรรดาปัจจัยที่มี** — ระเบียนหนึ่ง
  จึงไม่มีทางถูกอ่านว่าสดกว่าความจริง ส่วน `layer.observedAt` ของทั้ง run คือค่าที่ใหม่ที่สุด
  ในบรรดาสถานีทั้งหมด (นิยามเดียวกับ `latestObservedAt` ของชั้นค่าตรวจวัด)
- **`min_bank` ที่ต้นทางไม่ได้สำรวจ** จะไม่มี freeboard ให้คำนวณ ปัจจัยนั้นเป็น `null`
  ไม่ใช่ 0 (ถ้าเชื่อ 0 ตามตัวอักษร สถานีปกติจะถูกรายงานว่าน้ำล้นตลิ่ง)

## เวลาที่แสดงบนแผนที่

- `inputs.thaiwaterFetchedAt` / `layer.fetchedAt` — เวลาที่ backend ดึง ThaiWater สำเร็จ
  ครั้งล่าสุด **null = ยังไม่เคยสำเร็จ** และค่านี้ห้ามถูกแทนด้วยเวลาที่คำนวณ run
- `computedAt` — เวลาที่ run นี้ถูกคำนวณ คนละอย่างกับสองค่าข้างบน
- `observedAt` รายสถานี — เวลาที่เครื่องมือวัดจริง (ดูข้อจำกัดข้างบน)

## จะดูข้อมูลที่ตรวจวัดจริงได้ที่ไหน

- **สถานีวัดระดับน้ำ/น้ำฝน (ThaiWater สสน.)** — ค่าดิบที่ชั้นนี้ใช้ ดูได้ตรง ๆ บนแผนที่
- **พื้นที่น้ำท่วมจากภาพถ่ายดาวเทียม (GISTDA)** — สิ่งที่ตรวจพบแล้วจากภาพชุดล่าสุด
- **เรดาร์ฝน (กรมอุตุนิยมวิทยา)** — ภาพสะท้อนเรดาร์ย้อนหลัง 3 ชั่วโมง
