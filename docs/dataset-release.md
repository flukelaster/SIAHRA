# ปล่อยชุดข้อมูล tile หนึ่งรุ่น (E9.3)

เอกสารนี้คือ **ฉบับหลัก** ของลำดับการปล่อยรุ่นชุดข้อมูล tile และวิธีถอยเมื่อพลาด
`docs/dataset.md` §7 ชี้มาที่นี่ และยังเป็นเจ้าของอีกสองเรื่องที่ไม่ซ้ำกับที่นี่: รูปร่างของ URL
สองแบบ กับ **นโยบายห้ามลบ prefix เก่า** — อ่านที่นั่นก่อนถ้ายังไม่เคยอ่าน

คำสั่งเดียวที่ต้องรันคือ `scripts/release-dataset.sh` ซึ่งเป็นตัวบังคับลำดับทั้งหมดแทนคน

```bash
scripts/release-dataset.sh --version=2026-08-21 --dry-run   # ดูก่อนว่าจะทำอะไรบ้าง
scripts/release-dataset.sh --version=2026-08-21 --copy      # ของจริง (ไบต์ที่อยู่บน R2 แล้ว)
```

`--copy` คือรูปที่ใช้บ่อยที่สุดและเป็นรูปเดียวกับที่ `docs/dataset.md` §7 กับ `docs/deploy.md` §1
แสดงไว้: ไบต์อยู่บน prefix เดิมของ R2 อยู่แล้ว งานที่เหลือคือย้ายเข้า prefix ของรุ่น ถ้าเพิ่ง
build ชุดใหม่ในเครื่อง ให้ตัด `--copy` ออก (อัปจากเครื่องนี้) หรือใช้ `--build` — ดู §3

## ทำไมลำดับถึงเป็นหัวใจของงานนี้

tile ทุกไฟล์ถูกส่งด้วย `Cache-Control: public, max-age=31536000, immutable` ผลที่ตามมามีสองข้อ
และทั้งสองข้อ **แก้ย้อนหลังไม่ได้**:

1. **manifest ต้องชี้รุ่นใหม่หลังไบต์ขึ้นไปครบและตรวจผ่านแล้วเท่านั้น** — ชี้ก่อน = client ทุกเครื่อง
   ยิงหา tile ของรุ่นที่ยังไม่มีบน R2 แล้วได้ 404 ทั้งแผนที่
2. **ชื่อรุ่นที่ปล่อยไปแล้วห้ามใช้ซ้ำกับไบต์ชุดอื่น** — เบราว์เซอร์ที่แคช URL ของรุ่นนั้นไว้จะไม่ถาม
   ซ้ำอีกหนึ่งปีเต็ม การเอาชื่อเดิมไปใส่ไบต์ชุดใหม่จึงทำให้ผู้ใช้กลุ่มนั้นค้างอยู่กับของเก่าโดยไม่มีทางแก้
   (`apps/etl/src/datasetVersion.ts` เป็นคนบังคับกฎข้อนี้)

สคริปต์จึงเรียงงานเป็นห้าขั้นตายตัว และหยุดทันทีที่ขั้นใดขั้นหนึ่งไม่ผ่าน

## 0. สิ่งที่ต้องมีบนเครื่องที่รัน

- `rclone`, `jq`, `curl`, `git`, `npm` (`brew install rclone jq`)
- ชุด tile ที่ `apps/etl/data/tiles` (symlink จากดิสก์ที่เก็บชุดข้อมูลก็ได้ — `scripts/setup-worktree.sh` ทำให้)
- **คีย์ R2 สามตัว** ในไฟล์เดียว รูปแบบ `KEY=value` บรรทัดละตัว:

  ```
  CLOUDFLARE_ACCOUNT_ID=...
  R2_ACCESS_KEY_ID=...
  R2_SECRET_ACCESS_KEY=...
  ```

  ไม่มีไฟล์นี้ = สคริปต์ปฏิเสธตั้งแต่ยังไม่ทำอะไรเลย (ก่อนแม้แต่ `--dry-run` จะเริ่มพิมพ์ขั้นตอน)
  โดยบอกชื่อทั้งสามตัวและวิธีชี้ไฟล์ให้ — และไม่พิมพ์ค่าของคีย์ออกมาไม่ว่ากรณีใด

### คีย์อยู่ที่ไหน เมื่อทำงานใน worktree

`scripts/.env.r2` อยู่ใน `.gitignore` จึงมีอยู่แค่ใน checkout ที่ผู้ใช้สร้างมันขึ้นมาเอง (ปกติคือ
checkout หลัก) ส่วน worktree ที่เพิ่งสร้างจะไม่มีไฟล์นี้ติดมาด้วย เลือกทางใดทางหนึ่ง — **ห้ามคัดลอก
ไฟล์คีย์เข้ามาใน worktree** เพราะนั่นคือคีย์อีกหนึ่งชุดที่ต้องตามลบทีหลัง และลืมได้ง่ายที่สุด:

| วิธี | คำสั่ง | เหมาะกับ |
|---|---|---|
| symlink (แนะนำ) | `ln -s /path/to/main-checkout/scripts/.env.r2 scripts/.env.r2` | worktree ที่จะปล่อยรุ่นมากกว่าหนึ่งครั้ง |
| ตัวแปรแวดล้อม | `SIAHRA_R2_ENV=/path/to/scripts/.env.r2 scripts/release-dataset.sh …` | รันครั้งเดียว |
| ธง | `scripts/release-dataset.sh --env-file=/path/to/scripts/.env.r2 …` | รันครั้งเดียว, เขียนไว้ในบันทึกได้ว่าใช้ไฟล์ไหน |

ลำดับความสำคัญคือ `--env-file=` → `$SIAHRA_R2_ENV` → `scripts/.env.r2` และถ้ามีทั้งไฟล์ที่สั่งมาเอง
**และ** `scripts/.env.r2` อยู่ด้วยกัน สคริปต์จะหยุดและให้เลือกให้เหลืออันเดียว เหตุผลไม่ใช่ความเรียบร้อย:
`scripts/upload-tiles.sh` จะ `source scripts/.env.r2` ทับค่าที่ส่งต่อมาเสมอ ปล่อยไว้จึงเป็นการปล่อยรุ่น
ด้วยคีย์คนละชุดกับที่ผู้รันเลือก โดยไม่มีอะไรบอก

## 1. เงื่อนไขก่อนเริ่ม

**`siahra-web` ที่ deploy อยู่ต้องรู้จัก path แบบ `/v/{ver}` แล้ว** (โค้ด E9.2 —
`apps/web/worker/tilePath.ts`) ทั้ง `--smoke` และ `verify-tiles.sh` ยิง HEAD ผ่าน Worker ตัวจริง
Worker รุ่นก่อนหน้าจะไม่รับ path รูปนี้แล้วโยนให้ asset layer ซึ่งตั้ง
`not_found_handling: "single-page-application"` ไว้ **ผลจึงไม่ใช่ 404 แต่เป็น `200 text/html`**
(หน้า `index.html`) — "200" ที่ไม่ได้แปลว่าไบต์ถึงแล้ว คือความล้มเหลวที่อ่านผิดง่ายที่สุดใน
กระบวนการนี้ทั้งหมด และเป็น 200 ที่การนับสถานะอย่างเดียวจะรายงานว่า "ผ่าน"

**สัญญาณเดียวที่แยกได้จริงคือ `content-type`** วัดจริงบน prod ด้วย `curl -I` (2026-08-20):

| path | ผลจริง | ใครตอบ |
|---|---|---|
| `/aoi/11/terrain/0/0_0.bin` | `200 application/octet-stream` (+ `cache-control: …immutable`) | Worker อ่านจาก R2 = ไทล์จริง |
| `/aoi/11/v/2026-08-17/terrain/0/0_0.bin` | `200 text/html` | asset layer (SPA fallback) |
| `/aoi/11/terrain/0/9999_9999.bin` | `404 text/plain;charset=UTF-8` | Worker ตอบ 404 ของตัวเอง |

404 ของ Worker ที่ deploy อยู่ **ไม่มี header `Content-Security-Policy` เลย** (header ครบชุดคือ
date, content-type, report-to, nel, server, cf-ray, alt-svc) จึงใช้ CSP เป็นสัญญาณไม่ได้ —
ทุกจุดที่ยิงไทล์ (`worker_precondition`, `probe()` ใน `upload-tiles.sh`, การนับใน `verify-tiles.sh`)
บังคับว่า **ผ่าน = `200` และ `application/octet-stream`** เท่านั้น

สคริปต์ยิงสอง path เสมอ: path แบบมีรุ่น กับ path เดิมของ **ไฟล์เดียวกัน** เป็นตัวคุม —
ตัวคุมตอบ `200 application/octet-stream` แปลว่าเส้นทางเครือข่ายอ่านค่าจริงได้ ผลของ path แบบมีรุ่น
จึงสรุปได้ ด่านนี้ **ผ่านได้สองทาง** และทางที่เจอบ่อยที่สุดคือทางที่สอง:

- `200 application/octet-stream` — ไฟล์นี้เคยถูกอัปไปแล้ว (รันซ้ำรอบที่สอง)
- `404 text/plain` — **404 ของตัว Worker เอง** แปลว่า Worker รู้จัก `/v/` แล้ว แค่ยังไม่มีไฟล์นี้
  ในรุ่น ซึ่งเป็นสภาพปกติของรุ่นใหม่ที่ยังไม่ได้อัปอะไรเลย ไม่ใช่ความผิดพลาด

ถ้าตัวคุมเป็นไทล์จริงแต่แบบมีรุ่นเป็น `text/html` สคริปต์จะ **หยุด** และบอกให้
`npm run deploy:web` ก่อน (deploy โค้ดก่อนปลอดภัยเสมอ เพราะ manifest ทั้งหมดยังชี้ prefix เดิมอยู่)
ถ้าอ่านค่าไม่ได้เลยแม้แต่ตัวคุม — เครื่องที่อยู่หลัง TLS filter เจอได้ (`docs/deploy.md` §6) —
จะ **เตือนว่า "ตรวจไม่ได้" แล้วไปต่อ ไม่ใช่รายงานว่าผ่าน** เพราะขั้นถัดไปคือ `--smoke` ซึ่งเป็น
ไฟล์เดียว ล้มเร็ว และเช็ค content-type เหมือนกัน (จงใจไม่มีธง `--skip` ให้ข้ามด่านนี้)

อีกสองข้อที่สคริปต์บังคับก่อนเริ่ม:

- **`apps/web/public/aoi` ต้องไม่มีการแก้ค้าง** (เทียบกับ `HEAD` จึงนับของที่ `git add` ไว้แล้วด้วย)
  — ขั้นที่ 5 คือ `git diff HEAD` ของ manifest ซึ่งเป็นด่านตรวจ
  ด้วยตาด่านสุดท้ายก่อน deploy; diff ที่ปนของค้างมาก่อนหน้าอ่านไม่ออก = ด่านนั้นหายไปทั้งด่าน
- **`--copy` กับ `--build` ใช้ร่วมกันไม่ได้** — `--copy` ก๊อปไบต์ที่อยู่บน prefix เดิมของ R2 (ของเก่า)
  เข้ารุ่นใหม่ ถ้าเพิ่ง build ใหม่ในเครื่อง รุ่นใหม่จะบรรจุไบต์ชุดเก่าขณะที่ checksum ใน manifest
  บรรยายชุดใหม่ — ผิดชนิดที่ immutable หนึ่งปีทำให้แก้ไม่ได้

## 2. ห้าขั้น

| ขั้น | ทำอะไร | ล้มแล้วเป็นยังไง |
|---|---|---|
| 1 build | `npm run build:all -w apps/etl` — ทำเฉพาะเมื่อส่ง `--build` (ไม่ส่ง = ใช้ tile ที่มีอยู่ตามสภาพ) | ยังไม่มีอะไรเปลี่ยนนอกเครื่อง |
| 2 checksum | `refresh:manifests --dataset-version=$VER --dry-run` — คำนวณ checksum/`builtAt` ใหม่แล้วเทียบกับที่ manifest ประกาศไว้ **โดยไม่เขียนไฟล์** ด่านนี้ตอบคำถามเดียว: ชื่อรุ่นนี้ยังใช้ได้ไหม | หยุดก่อนลงทุนอัป — ดู §5 |
| 3 upload | `upload-tiles.sh --version=$VER [--copy] --smoke` (ไฟล์เดียวก่อนเสมอ) แล้วจึงทั้งชุด | prefix เดิมยังเสิร์ฟอยู่ ผู้ใช้ไม่เห็นอะไรผิด |
| 4 verify | `VERSION=$VER verify-tiles.sh` — ต้องบังคับรุ่น เพราะ manifest ยังประกาศรุ่นเก่า ปล่อยว่างจะกลายเป็นการตรวจรุ่นก่อนหน้าแล้วผ่านฉลุยโดยไม่ได้ตรวจรุ่นใหม่เลย | manifest ยังไม่ถูกแตะ |
| 5 manifest diff | `refresh:manifests --dataset-version=$VER` ของจริง แล้วโชว์ `git diff --stat` กับบรรทัด `urlTemplate` ที่ถูกชี้ใหม่ | ดู §5 (tree ผสม) |

**AOI สาธิต `chiangmai-old-city` เปลี่ยนไม่เท่ากับจังหวัดอื่น** — ขั้นที่ 5 จะเลื่อน
`provenance.datasetVersion` ของมันตามรุ่นใหม่ แต่ **ไม่** เขียน `urlTemplate` ให้เป็น prefix แบบมีรุ่น
เพราะ `apps/web/worker/tilePath.ts` เสิร์ฟเฉพาะรหัสจังหวัดสองหลัก การชี้ AOI นี้ไปที่ `/v/…` จึงเท่ากับ
404 ทุกไทล์บน prod ขณะที่ dev ยังเขียว (`retargetTileTemplates()` เป็นคนกันไว้ พร้อมพิมพ์เหตุผลหนึ่งบรรทัด)
ใน diff จึงเห็น 78 ไฟล์เปลี่ยน แต่บรรทัด `urlTemplate` มีแค่ 77 จังหวัด × 4 ชั้น

ขั้นที่ 4 ยังตรวจซ้ำอีกชั้นว่า `verify-tiles.sh` "ได้ตรวจอะไรจริง ๆ" ไม่ใช่แค่ exit 0: ถ้ารายการ path
ที่มันตรวจว่างเปล่า มันจะไม่มีอะไรให้ fail แล้วพิมพ์ ✅ ออกมา สคริปต์จึงนับจำนวน path แบบมีรุ่นที่
ตอบ `200 application/octet-stream` และบังคับว่าต้องได้อย่างน้อยจังหวัดละสอง (ของจริงได้ราวจังหวัดละ 8
= 4 ชั้น × z ตื้นสุด/ลึกสุด — เกณฑ์ตั้งต่ำไว้เพราะมันมีไว้จับ "ผ่านเพราะไม่ได้ตรวจอะไรเลย"
ไม่ใช่ไว้เดาจำนวนไทล์) — การตรวจที่ไม่ได้ตรวจอะไร ห้ามปลดล็อกขั้นที่ 5

ขั้นที่ 4 ยัง **หยุดทันทีถ้า `verify-tiles.sh` พิมพ์ `MISSING_LOCAL`** ซึ่งคนละเรื่องกับเกณฑ์ข้างบน:
มันแปลว่าชุด tile ในเครื่องนี้ขาดบางชั้นไป ไม่ใช่ว่าการตรวจอ่อนไป — ปล่อยรุ่นจากชุดที่ไม่ครบ =
ไทล์หายทั้งชั้นแบบถาวรใต้ชื่อรุ่นนั้น และตัว `verify-tiles.sh` เองก็ปฏิเสธสองกรณีนี้ในตัวมันเองแล้ว:
"ไม่มี path ให้ยิงเลย" (ตรวจศูนย์รายการแล้วพิมพ์ ✅) และ "จำนวนผลที่กลับมาไม่เท่ากับจำนวนที่ตั้งใจยิง"
(มีอะไรตายกลางทาง — ผลที่ไม่ครบสรุปไม่ได้ว่าไบต์ขึ้นครบ)

เกณฑ์นี้จะกันของจริงได้ก็ต่อเมื่อ "ผ่าน" หมายถึงไบต์ไทล์ — ถ้านับแค่สถานะ `200` หน้า `index.html`
ที่ asset layer ตอบให้ทุก path จะทำให้ทั้ง 616 path "ผ่าน" และข้ามเกณฑ์ขั้นต่ำไปได้อย่างสบาย
ทั้งที่ยังไม่มีไบต์อยู่จริงสักไฟล์เดียว (ดู §1)

**สิ่งที่สคริปต์ไม่ทำให้ โดยตั้งใจ**: ไม่ `git commit`, ไม่ `npm run deploy:web` — ขั้นที่ 5 จบลงที่
diff บนจอเพื่อให้คนอ่านก่อนตัดสินใจ

## 3. ตัวอย่าง

```bash
# ดูก่อนว่าจะเกิดอะไรขึ้น (ไม่มีไบต์ขึ้น R2, ไม่มี manifest ถูกเขียน, ไม่ยิงเน็ตเลยสักครั้ง)
scripts/release-dataset.sh --version=2026-08-21 --dry-run

# ย้ายชุดที่อยู่บน R2 อยู่แล้วเข้า prefix ของรุ่น (ไบต์ไม่วิ่งผ่านเครื่องนี้ — S3 CopyObject)
scripts/release-dataset.sh --version=2026-08-21 --copy

# build ใหม่ทั้งชุดแล้วอัปจากเครื่องนี้ (หลายชั่วโมง)
scripts/release-dataset.sh --version=2026-08-21 --build

# เฉพาะบางจังหวัด + สุ่มตรวจเพิ่มจังหวัดละ 20 ไฟล์ในขั้นที่ 4
scripts/release-dataset.sh --version=2026-08-21 --sample=20 11 12 13
```

ปล่อยรุ่นสองครั้งในวันเดียวกันใช้ `.N` ต่อท้าย เช่น `--version=2026-08-21.1` (รูปแบบเดียวกับที่
`worker/tilePath.ts` และ `datasetVersion.ts` ยอมรับ — ค่าที่ผิดรูปจะถูกปฏิเสธตั้งแต่บรรทัดแรก)

รันซ้ำด้วยรุ่นเดิมได้เสมอถ้ารอบก่อนไปไม่สุด: ทุกขั้นเป็น idempotent และ `rclone copy` ไม่ลบอะไรเลย
— ยกเว้นกรณีเดียวคือ **ไบต์ในเครื่องเปลี่ยนไปหลังจากอัปรอบแรกไปแล้ว** ตอนนั้นต้องเปลี่ยนชื่อรุ่น

## 4. หลังสคริปต์จบ

```bash
git add apps/web/public/aoi && git commit    # 1. อ่าน diff ที่ขั้นที่ 5 พิมพ์ไว้ก่อน
npm run deploy:web                           # 2. manifest ถูก track และ ship ไปกับ deploy unit เดียวกัน
scripts/verify-tiles.sh                      # 3. ตรวจซ้ำโดยไม่บังคับรุ่น — ค่าที่อ่านได้ต้องเป็นรุ่นใหม่เอง
```

ขั้นที่ 3 ต่างจากขั้นที่ 4 ของสคริปต์ตรงที่ไม่ตั้ง `VERSION=` ให้: มันอ่าน
`provenance.datasetVersion` จาก manifest ที่เพิ่ง deploy ไป จึงเป็นการยืนยันว่า "สิ่งที่ manifest บอก"
กับ "สิ่งที่อยู่บน R2" ตรงกันจริง ไม่ใช่ตรงเพราะเราบอกมันเอง

## 5. ถอย

**ความไม่สมมาตรที่ทำให้การถอยถูกมาก**: prefix เดิม (`aoi/{code}/{layer}/…`) ไม่เคยถูกแตะเลยตลอด
กระบวนการนี้ — ไม่มีขั้นไหนลบหรือเขียนทับมัน และ `docs/dataset.md` §7 ห้ามลบมันไม่มีกำหนดอยู่แล้ว
มันจึงยังเสิร์ฟอยู่ตลอดเวลา ผลคือ **การถอย = เอา manifest กลับไปเป็นของเดิมแล้ว deploy ใหม่** เท่านั้น
ส่วนไบต์ที่อัปขึ้นไปแล้ว **ปล่อยทิ้งไว้ ไม่ต้องลบ** (ต้นทุนคือค่า storage ~5.2 GiB ต่อชุด — §7 มีตัวเลข)

```bash
git checkout -- apps/web/public/aoi   # หรือ git revert <sha> ถ้า commit ไปแล้ว
npm run deploy:web
```

| พังตอนไหน | ผู้ใช้เห็นอะไร | ทำอะไร |
|---|---|---|
| ขั้น 1 build | ไม่มีอะไรเปลี่ยน | แก้เหตุแล้วรันใหม่ |
| ขั้น 2 checksum guard ยิง | ไม่มีอะไรเปลี่ยน | **ตั้งชื่อรุ่นใหม่** แล้วรันใหม่ (ดูกรอบข้างล่าง) |
| ขั้น 3 upload ล้มกลางคัน | ปกติ — manifest ยังชี้ prefix เดิม | รันสคริปต์ซ้ำด้วยรุ่นเดิม `rclone copy` จะทำต่อจากที่ค้าง ไม่ลบอะไร |
| ขั้น 4 verify ไม่ผ่าน | ปกติ | อ่านบรรทัดสรุปของ `verify-tiles.sh`: "prefix เดิมไม่ผ่าน" = ของเก่าหาย (ร้ายแรงกว่ามาก) · "แบบมีรุ่นไม่ผ่าน" = ยังก๊อปไม่ครบ หรือ Worker ยังไม่รู้จัก `/v/` |
| ขั้น 4 เจอ `MISSING_LOCAL` | ปกติ | ชุด tile ในเครื่องขาดบางชั้น ไม่ใช่ปัญหาฝั่ง R2 — symlink dataset ให้ครบ (หรือ `--build`) แล้วรันใหม่ด้วยรุ่นเดิม |
| ขั้น 5 refresh ล้มบางส่วน | ปกติ (ยังไม่ deploy) | `refreshManifests.ts` ทำต่อจนจบแล้วค่อยคืนค่าไม่ศูนย์ = **บาง manifest ถูกเขียนไปแล้ว** ห้าม deploy สภาพนี้ → `git checkout -- apps/web/public/aoi` แล้วหาสาเหตุ |
| ขั้น 5 เจอ `urlTemplate` ที่ไม่ได้ชี้ `/v/$VER/` | ปกติ (ยังไม่ deploy) | manifest ถูกเขียนไปแล้วแต่มีบรรทัดที่ชี้ผิด สคริปต์หยุดก่อน commit — ถอยเหมือนแถวบน แล้วดู `git diff` เต็ม ๆ ว่าจังหวัดไหนหลุด |
| หลัง deploy: tile 404 เป็นรู | เห็นจริง | ถอย manifest + `npm run deploy:web` หรือถ้าเพิ่ง deploy ไปสด ๆ ใช้ `npx wrangler rollback <deployment-id> --config apps/web/wrangler.jsonc` ก็ได้ผลเดียวกันเร็วกว่า แล้วค่อยตามแก้ให้ครบ |

> **ชื่อรุ่นที่เคยไปถึง manifest ที่ deploy แล้ว ถือว่าถูกเผาไปแล้ว** ถอยแล้วก็ยังห้ามใช้ซ้ำ เพราะมี
> ไบต์อยู่ใต้ชื่อนั้นบน R2 และมี client ที่แคช URL ของมันไว้ รุ่นถัดไปต้องเป็นชื่อใหม่เสมอ
> (`2026-08-21` → `2026-08-21.1`)

**ห้ามทำ**: `rclone delete` ไบต์ของรุ่นที่ถอยแล้ว เงื่อนไขเดียวที่ลบได้อยู่ใน `docs/dataset.md` §7
(เฉพาะรุ่นกลางที่ไม่มี manifest ไหนชี้ และเก่ากว่า `max-age` เต็มปี)

**ห้ามทำเช่นกัน**: รันขั้นที่ 2 ซ้ำด้วย `--allow-version-reuse` เมื่อ guard ยิง ธงนั้นมีไว้สำหรับ
กรณีเดียวคือรุ่นที่ **ยังไม่เคยอัปขึ้น R2 เลย** การใช้มันกับรุ่นที่ปล่อยไปแล้วคือการทำให้ client ที่
แคช immutable ไว้ค้างอยู่กับไบต์ชุดเก่าอีกหนึ่งปีโดยไม่มีทางแก้ — ทางแก้ที่ถูกมีทางเดียวคือชื่อรุ่นใหม่
สคริปต์จึงพูดถึงธงนี้เพื่อ **ห้าม** เท่านั้น ไม่เคยเสนอให้ใช้

## 6. คำถามที่คนถามซ้ำ

- **ทำไม dry-run ถึงยังต้องมีคีย์ R2** — เพราะสิ่งที่ dry-run มีค่าที่สุดคือการพิสูจน์ว่า "รันจริงแล้วจะไม่
  ไปตายกลางทาง" การไม่มีคีย์คือความล้มเหลวที่ถูกที่สุดที่ควรเจอตั้งแต่วินาทีแรก ไม่ใช่หลัง build หกชั่วโมง
  (dry-run อ่านไฟล์คีย์เพื่อดูว่ามีครบสามตัวไหมเท่านั้น ไม่ยิงเน็ต ไม่พิมพ์ค่า)
- **`--smoke` ก๊อปไฟล์ของจังหวัด 11 เสมอ แม้ปล่อยแค่บางจังหวัด** — จริง และไม่เป็นไร: มันคือไทล์ของ
  จังหวัด 11 ก๊อปเข้าไปใต้ prefix ของรุ่น ซึ่งเป็นไบต์ชุดเดียวกับที่จังหวัดนั้นจะเสิร์ฟอยู่แล้ว อย่างมาก
  ก็เป็นออบเจ็กต์กำพร้าหนึ่งชิ้นที่ไม่มี manifest ไหนชี้
- **ทำไมสคริปต์ไม่ deploy ให้** — เพราะ diff ของ manifest คือจุดสุดท้ายที่คนยังหยุดได้ทัน หลังจาก
  `deploy:web` ไปแล้ว ทางออกมีแค่ถอยตาม §5
