## Why direct aggregation, not "illustrative"

Both the population zonal sum (summing real WorldPop pixel values inside a real
boundary polygon) and the OSM counts/lengths are direct aggregation of a
published, citable dataset over a real geometry — not a model this project fit,
and not a forecast. All four sections' `HazardLayerDescriptor.epistemicClass` is
therefore `static-reference`, the same class the WorldCover/Copernicus DEM static
layers already use, not `illustrative` (which is reserved for a DEM-derived
approximation this project computed with no claim of calibration).

  zero population failures, zero zero-population results (every gdalwarp crop
  produced at least one valid, non-negative, non-nodata pixel).
- **Population**: sums to **11,882,241** across the 431 authorities (min 391,
  max 569,818 — เทศบาลนครนนทบุรี, `TH-LAO-3120102`, a dense inner-Bangkok-metro

## `buildingsPerThousandPop` — a raw ratio, not a confidence score

Median **3.63** buildings per 1,000 population; **240 / 431** authorities (56%)
are below 5/1000 — this flags areas where OSM's building layer is likely
under-mapped relative to how many people WorldPop estimates live there, not
areas that genuinely have almost no buildings. Treat a low ratio as "OSM
coverage here needs checking," not as ground truth about built density.

## A real tagging bug this run caught and fixed

The original task spec called for extracting fire stations via
`emergency=fire_station`. Before trusting a "0 fire stations, every authority"
result, this was checked against the real cached extract directly:

```
osmium tags-filter thailand-latest.osm.pbf "amenity=fire_station" -o /tmp/a.pbf
# -> 894 nodes, 137 ways nationally
osmium tags-filter thailand-latest.osm.pbf "emergency=fire_station" -o /tmp/b.pbf
# -> 0 nodes, 0 ways nationally
```

The real, standard OSM tag for a fire station is `amenity=fire_station`; the
`nwr/amenity=hospital,school,fire_station` filter now used in
`buildLocalAuthorityExposure.ts` reflects that. Reporting "0 fire stations
everywhere" from the wrong tag would have been a data-honesty violation — a
tagging bug misreported as a real absence, not "the source is quiet."

## Facility dedup

Hospitals/schools/fire stations in OSM are sometimes mapped as both a point
(POI node) *and* a building/area with the same amenity tag for the same
physical place. `dedupeFacilityNodes` drops any node that falls inside a
same-type facility polygon already collected for that province, so the
polygon-derived centroid stands in for it once rather than counting the same
facility twice.

  30,920 buildings, 462 km of roads, 5 hospitals / 21 schools / 3 fire

  — matches the right order of magnitude for the city municipality.

  to population (8.7/1000), flagged by `perThousandPop` as likely under-mapped
  in OSM rather than a real absence of buildings.
